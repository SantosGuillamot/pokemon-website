# Radical Pipelines Conventions

Project conventions for Radical Pipelines. Agentic coding tool: Claude Code.

## Branch name base

Format: `feature/<short-description>` — a hyphenated slug derived deterministically
from the issue. Valid git ref, no `_` (reserved as the pipeline grammar's segment
separator). The pipeline appends its own segments after the base.

Example: issue "Special Attack page" → `feature/special-attack`.

## Pipeline family folder

`.pipelines/<short-description>/` — one folder per issue holding all phase artifacts
across the issue's pipelines. Deterministic from the issue, identical across runs.

Example: `.pipelines/special-attack/`.

## Issues

Issues are tracked as Markdown files under `.claude/issues/`. Each file — or a numbered
file inside a family subfolder, e.g. `.claude/issues/meta-pokemons/02-...md` — is one
issue. Read, comment on, and update an issue by reading and editing its Markdown file
directly. Note: `.claude/` is git-ignored, so issues are local-only and not committed.

## Worktree root

`.claude/worktrees/` — the orchestrator creates one worktree per branch here with raw
`git worktree`, and removes each when its work is done. Already covered by the `.claude`
entry in `.gitignore`.

## Commit format

`<commit-description> (<agent-name>)`

Example: `Add Special Attack data table (build-writer-tdd)`.

## Team spawning

Spawn each agent as a Claude Code teammate. A teammate runs in the shell working
directory its sender was in at the last send: a spawn starts it there, and every message
restarts it there — whoever the sender is. A directory change inside a teammate does not
persist to its next command. To seat an agent, at every send — spawn or message: `cd`
into its worktree, send, then `cd` back. Never use Claude Code's worktree tools
(`EnterWorktree`/`ExitWorktree`) during a run — a worktree switch is session-wide and
retargets the working directory of every running agent. A teammate's spawn result
includes its `agentId` — the identifier for addressing messages to it.

## Health monitoring

Use Claude Code's bundled `/loop` skill — no install is required.

- **Start:** `/loop 5m <prompt>` where `<prompt>` is the template from
  `reference/health-monitoring.md`, appending each agent's worktree path and the seating
  rule: a message restarts its target in the sender's shell working directory, so `cd`
  into an agent's worktree before messaging or restarting it, then `cd` back.
- **List active loops:** the `CronList` tool.
- **Cancel:** the `CronDelete` tool with the loop's task id.

## Guardrails

### lint

- command: `npm run lint`
- agents: build-writer-tdd, build-writer-e2e, build-reviewer

### typecheck

- command: `npx tsc --noEmit`
- agents: build-writer-tdd, build-writer-e2e, build-reviewer

## Artifact storage

- mode: `artifacts-in-repo`

All Radical Pipelines artifacts (`.rp.md`, the `.pipelines/` family folders, and
per-phase commits) live in this repository on the `trunk` branch. Single remote:
`origin` (https://github.com/SantosGuillamot/pokemon-website.git).
